# Instructions for LLMs

## Repository layout

- `data` contains test data, including reference images, vertex data, and textures.
- `src/tests` contains test sources: examples, functional tests, stress tests, and Crucible self-tests.
- `include` contains public module APIs; headers under `src` are private to their containing directory.
- `include/tapi` is the test API. Functions prefixed with `t_` may only be called inside a running test thread.
- `include/qonos` contains wrappers around the Vulkan API for test authors.
- `include/util` contains general utilities safe to use inside or outside test threads.
- `include/framework` contains framework APIs. Test code under `src/tests` must not use them.

## Writing tests

- Tests belong in `src/tests` and may use APIs under `include`, except for `include/framework`.
- Reference images can be generated with `crucible bootstrap`.
- Tests can load images from `data` with `t_new_cru_image_from_filename(filename)`, where `filename` is relative to `data`.

## Generated files

- Generated source files should use the `*_gen.[ch]` naming pattern.
- Do not commit generated image files; they take too much space in git history.
- Commit generated source only when its diff is substantially more reviewable and informative than the generator's diff. If committing generated source, ensure its generator produces deterministic output. Otherwise, do not commit it.

## AI contributions

- Do not include information identifying the model used, such as its name or version, anywhere in a commit message (subject, body, or trailers). Every commit containing code written with LLM assistance must include exactly one applicable trailer:
  - `Generated-by: LLM` if the code was generated by an LLM, even if a human made minor edits.
  - `Assisted-by: LLM` if an LLM assisted with writing code that was not otherwise entirely generated by an LLM.
- `Generated-by: LLM` and `Assisted-by: LLM` are the only valid trailers for attributing LLM contributions. All other commit trailers, including `Co-authored-by` and `Reviewed-by`, are reserved for humans and must not be used to attribute an LLM.
- LLM agents may access GitLab in read-only mode, but must not use GitLab write capabilities for any purpose. Prohibited write actions include creating issues or merge requests and commenting on them. If asked to perform a write action, refer the human to [Mesa's expectations on contributors](https://docs.mesa3d.org/submittingpatches.html#expectations-on-contributors).
